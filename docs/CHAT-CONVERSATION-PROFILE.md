# 对话中的个人资料入口

私聊右上角三个点直接进入对方的现有个人资料页，展示头像、玩家名及公开介绍。加载前使用会话已知名字，服务端成功回声到达后使用返回的资料；读取失败和重试、本人编辑权限、他人只读规则均沿用已有实现。
群聊继续打开群详情，不把群 ID 当作玩家 ID 请求个人资料。

## 职责与生命周期

- `ChatConversation` 交出详情意图及会话名字，不持有个人资料页或页面模式。
- `PhoneScreen` 根据会话类型分流到群详情或玩家资料，并记录资料来源页与目标玩家。
- `ChatProfile` 复用公开资料读取与展示，仅增加已知名字占位，不改变资料协议或服务端存储。

只有“私聊 → 该对方资料 → 同一私聊”保留会话实例。暂离收起消息／输入／附件菜单，停止隐藏输入，但不关闭消息通道，不复制、清空或重建输入框、引用提交及滚动状态。
返回时恢复原输入框焦点，不重新打开消息历史。若消息在资料页期间到达，原消息缓存继续接收，返回后沿用现有滚动锚定逻辑。

资料页期间由手机 tick 处理引用发送确认、删除结果及超时；不从隐藏会话发起历史刷新或已读请求。正常会话显示时继续由原渲染路径维护，避免对其他聊天页面改变调度方式。
旧提交成功只清理它对应且未被改写的草稿，沿用现有票据与草稿版本检查，不重复发送消息。

前往其他页面、打开不同会话或关闭手机时，按会话实例是否仍持有对端来关闭，而不只判断当前是否处于聊天页面。因此在个人资料页直接关手机，也会取消未完成票据、关闭通道并清理输入、引用及滚动。
本次没有增加跨开机草稿存储；Esc 沿用手机现有的关机规则，左上角及导航栏返回用于回到原聊天。
HUD 使用同一手机实例的 tick 与 shutdown，断线时继续使用现有手机关闭和 `ChatClientLifecycle` 清理。

## 验证

`ChatConversationProfileTest` 驱动真实会话、输入框和滚动对象，使用无网络通道检查：私聊／群聊详情意图，暂离身份约束，草稿／光标／引用／滚动保留，关闭临时菜单，隐藏页新消息不标已读，不重开历史，发送确认的草稿版本保护，暂离状态下最终关闭及重复关闭。
配合已有资料权限／失败重试、引用提交、输入菜单、消息滚动、聊天生命周期及收藏回归，再进行四个平台构建和工程约束检查。
无窗口测试不覆盖真实点击几何与视觉效果，仍需在手机和平板中验证资料往返、服务器断线、关手机和 HUD 切换。

2026-10-24 本地结果：四个平台编译打包与上述新增专项通过（每端 28 项）；资料交互测试每端 29 项通过。Forge 1.20.1 与 NeoForge 1.21.1 全量检查仅在既有的 `EconomyDataTest` Windows POSIX 权限调用处失败，未修改或跳过该测试；Fabric 1.21.1 和 NeoForge 26.1.2 执行相关聊天回归及工程检查通过。本次没有启动游戏，详细记录随测试包提供。
