# 群聊第一版

美西螈支持选好友建群、首页会话搜索、联系人 A–Z 群目录、群名与人数、发送者昵称、文字与图片、选字复制、个人删除、成员列表、邀请与本人同意/拒绝、群主改名、退出和群主解散。群公告、管理员、@、语音及免打扰继续预留。现有私聊存档和包格式不变。

## 参考与取舍

- [Tinode API](https://github.com/tinode/chat/blob/master/docs/API.md) 的群 topic 独立身份、成员访问权限和消息序号，使群会话不必伪装成双人会话。MCPhone 同样使用独立群 ID 和服务器序号，但沿用 Minecraft 连接与世界存档，不引入它的服务器、WebSocket 或数据库。
- [Matrix 的房间历史可见性](https://spec.matrix.org/v1.16/client-server-api/#room-history-visibility) 区分成员资格和历史可见性。MCPhone 创建者保留完整历史，新成员只有本人同意后才获得成员资格，只可读取同意时序号之后的消息；退出或解散立即失去读取与图片下载权限。重新入群也需重新同意。

这里只借鉴公开的设计，不复制项目源码、不引入外部依赖。权限检查在服务端完成，不以客户端是否显示按钮为依据。

## 文件分工

| 目录 / 类型 | 职责 |
| --- | --- |
| `shared/.../feature/chat/group/GroupBook` | 可独立测试的建群、成员索引、权限、消息序号、个人删除和已读规则 |
| `GroupRoom / GroupMember / GroupMessage` | 不可变完整状态与昵称快照，包含存档 codec |
| `GroupSummary / GroupInfo` | 个人会话摘要与独立成员资料，不向非成员发送 |
| `GroupData` | 主世界 `mcphone_groups.dat`，格式版本 3；读取旧格式 1/2，群状态和待处理邀请一起保存，坏数据或未知版本锁定并保留原文 |
| `GroupInvitation / GroupInvitations` | 不可变邀请、群/收件人索引、批次准备、去重、到期及撤销；不直接创建成员资格 |
| `GroupInviteNotice` | 只发给被邀请者的群名/邀请人资料，不携带成员清单、消息或图片身份 |
| `GroupService` | 连接玩家身份、手机、好友关系、服务器消息和保存协调，不构造包 |
| `GroupImageFiles / GroupImageAssembly` | 独立群图片目录、去重、引用回收、后台 IO 与上传分片/票据隔离 |
| `group/net/GroupCommand / GroupReply / GroupWire` | 明确的请求/响应数据与有界编解码；正文 codec 由版本层注入 |
| `GroupServer / GroupThrottle` | 服务端传输协调、分命令限流、成员推送与异步完成后二次鉴权 |
| `GroupClientCache` | 只有数据的群快照、历史票据、删除确认和操作结果，不引用客户端类 |
| `shared/.../feature/chat/client/ChatGroupCreate` | 群名称、好友搜索、多选和建群确认 |
| `ChatGroupDetails` | 详情内页面协调、权限提示、操作票据与离群确认，不代替服务端权限 |
| `ChatGroupMemberGrid` | 方形头像网格、完整成员滚动列表与邀请入口，共用布局和命中 |
| `ChatGroupNotices` | 联系人群通知内的邀请列表、同意/拒绝按钮与操作确认，不自行修改成员或目录 |
| `ChatGroupInvite / ChatGroupRename` | 好友搜索与多选、群名草稿；只交出选择/文字，不发送包或修改缓存 |
| `ChatGroupAvatar / ChatGroupEvents` | 方形拼合头像与群通知 |
| `ChatConversationChannel` | 私聊与群聊的缓存/命令适配器，消息组件不依赖具体协议 |
| `GroupTransport` | 客户端请求门面与共用摘要轮询时钟 |
| `ChatList / ChatContacts` | 群会话与 A–Z 群目录，群导航意图与私聊明确区分 |
| `ChatConversation / ChatMessagePane / ChatImageSender` | 共用输入、气泡、选字、复制、删除菜单、图片查看与上传队列 |
| `layers/version/1.20.5+/.../group/net/GroupRequestPacket / GroupResponsePacket` | 现代 payload / StreamCodec 包装 |
| `platforms/1.20.1-forge/.../group/net/GroupRequestPacket / GroupResponsePacket` | 老 Forge 编解码包装 |
| NeoForge loader 层、Forge/Fabric 平台的 `GroupNetworking` | 只注册与安装传输回调；两版 NeoForge 共用一份，追加在所有既有包之后 |

首页加号菜单的选择在同一次点击内交由宿主跳转，不等待下一次普通点击。建群至少选择一位好友；群名选填，未填或仅空白时使用“新群聊”。没有选人时显示明确提示；提交后禁用重复点击，服务端拒绝或超时后保留群名和选择，允许重试。

群内部实现不进入公共脚本 API；前端页面和网络处理不直接读写群存档。保存、协议、服务器规则和渲染之间只有明确的数据与命令接口。

## 当前规则与容量

- 群创建者是群主；创建群时只建立创建者资格，其选中的好友收到待处理邀请。所有现有群成员也可从详情页邀请自己的好友。离线邀请保存于世界存档，玩家上线打开联系人“群通知”后处理，同意前不会进入群目录、计入人数或获得消息/图片读取权限。
- 每批先完整校验好友、群人数及个人群配额，再写入邀请，不留下残余群或半批邀请。每群的正式成员和待处理邀请合计最多 128 人，每人待处理邀请最多 64 条、每世界最多 8192 条，有效期 7 天。重复邀请同一群的同一被邀请者只保留原票据，不重复通知或续期。
- 只有被邀请者本人能同意/拒绝，并且请求必须同时匹配邀请 ID 和群 ID。同意时再检查好友、邀请人仍在群内、群容量及本人群数量。成功才写入成员、索引、已读和入群时间；拒绝只移除邀请。已处理票据不能重放；过期、邀请人离群或解散会撤销未处理邀请。
- 新成员的入群边界取“同意”的服务器消息序号，与已读一起保存；等待同意期间的文字、图片、预览和未读均不可见，猜测图片或消息 ID 也不能绕过检查。重新入群不会恢复之前的个人记录。旧格式已加入成员和已有历史边界保留；格式 3 防止旧实现忽略或覆盖待处理邀请。
- 只有群主可修改群名称，最多 32 字符且不能为空。界面预填已确认名称，拒绝/超时保留草稿；收到成功确认前不改名。邀请、改名后回到当前详情，退出/解散成功才返回群列表。
- 群名最多 32 字符；每群上限 128 人、每人最多 32 群、每世界最多 4096 群。现有好友上限为 100，因此当前建群选择实际受好友上限约束。
- 每群保存最近 100 条消息；服务器产生消息 ID、发送者、昵称、时间和单调递增序号。相同毫秒的消息仍能正确排序和计未读。
- 个人删除保存在本人的群记录里，其他成员仍能看到；删除项不计入本人预览和未读。标记随对应旧消息淘汰，不无限增长。
- 退出后群从本人目录移除，成员索引、已读与个人删除标记一同移除。其他人的历史仍保留退出成员的消息和当时昵称。群主使用解散，第一版没有群主转让。
- 解散移除整个群及成员索引，不影响任何私聊。
- 群图片目录是世界内 `mcphone/group-images`，与私聊图片分开。每群保留最近 20 个不同图片 ID 的像素；更早消息可保留元数据并显示图片已过期。个人删除不会回收他人仍可访问的像素。
- 图片复用既有尺寸、字节数、动画帧数和分片上限。每条连接仅一份群分片任务，必须匹配群 ID、请求票据、元数据和片序；后台写入完成后再次检查连接、手机和成员资格。
- 首次群请求后台清理无引用图片；写入和回收共用锁，正在上传的相同图片使用引用计数保护。
- 图片完整写入同目录临时文件后再替换最终文件；失败不留下可被去重认领的半份最终文件。重复上传比较有界内容，既有截断或同长度损坏文件会重写。没有新增 fsync，不承诺断电耐久性。
- 服务端保存遵循原有世界保存机制。正常退出/保存后持久保留，未承诺强杀游戏前的即时刷盘。

## 网络与客户端一致性

当前完整功能使用 Forge 通道协议 11、NeoForge 注册协议 8（群开发阶段分别为 10/7，个人资料接入后再推进）；现代群 payload 为 `group_request_v3` / `group_response_v3`，Fabric 双向检查新群通道和资料通道。客户端与服务端必须同时更新，避免在旧服务端上发送新协议。没有改动模组版本号。群状态使用显式固定编号，不依赖枚举声明顺序。

发送邀请只向被邀请者推送通知，发送方显示“等待对方同意”，不提前更新成员数。本人同意后才向当前在线成员推送带版本的群资料并刷新目录；改名与退出同样同步。成员详情、较旧历史和推送按群 ID/请求票据/资料版本隔离，旧响应不能覆盖新的名称或成员数。群资料推送不清空消息、不冒充聊天消息、不触发聊天通知。

首页搜索复用联系人原版输入控件和名称匹配规则，两页共用 12 像素搜索栏高度及“搜索”提示，支持中英文、大小写与全角归一化，按好友名或群名过滤已有会话并保持时间排序。它不搜索消息全文，也不向服务端发送关键字。查询变化立即清掉旧行悬停和传送目标，下一帧重置滚动；菜单开启时先处理菜单，搜索焦点先于背包快捷键处理。传送图标透明底，移除外框但保持原点击区域。

群历史必须匹配当前群和本次历史请求；先到的新消息与后到的历史按服务器序号合并。删除成功快照、版本下限和请求票据防止旧历史复活个人删除。离开页面后取消操作票据，迟到确认不能把玩家带回旧页面。切服清空群目录、消息、成员资料和操作结果。

格式 2/3 必须包含 `joined_after` 历史边界，缺失或类型错误时锁定并保留原 NBT；仅格式 1 的专用迁移 codec 允许缺省，保留原有成员历史。客户端轮询、操作超时和待确认数量由 `GroupClientPolicy` 集中维护；断线统一经过 `ChatClientLifecycle`，同时取消群传输中的文字确认票据。

群和私聊使用分离缓存与导航意图，即使 UUID 相同也不会混用。图片上传队列记录目标类型，群回声同时匹配群 ID 与请求票据；选照片、表情和拖入图片后返回原来的会话类型。群消息弹窗按群合并，与私聊弹窗使用不同身份；邀请收件箱另有独立快照和确认票据。

HUD 在其他界面关闭后恢复绘制时，会重新绑定当前群缓存；同群连续帧保持快照，不重复清空或请求。离群状态也按当前群判断，不影响另一设备保留的不同群会话。

## 验证与游戏验收

群头像根据人数居中组合：两人横排、三人上单下双、四人四宫格，调用方只画一层底框。群消息的头像从行顶部开始，昵称使用 0.50 倍字号（正文 0.75 倍），距离气泡一行细间距；收发两侧都显示昵称，接收昵称左对齐，己方昵称按正文列右对齐。长昵称使用整个正文列截断，不受短气泡宽度限制。文字与图片共用同一昵称布局，私聊仍保留原来的短气泡底边对齐。

排版缓存包含会话类型；绘制、选字和右键命中共用本帧气泡位置。昵称不加入消息正文，也不会被拖选或复制进正文。

新增断言覆盖真实业务和 NBT 重载、缓存顺序与删除、连接/票据分片隔离、四平台实际包包装、生产选人点击和设备续开：`GroupBookTest`、`GroupClientCacheTest`、`GroupImageAssemblyTest`、`GroupPacketCodecTest`、`ChatGroupInteractionTest`。`GroupInviteTest`、`ChatHomeSearchTest`、`ChatGroupDetailsTest` 和 `ChatGroupNoticesTest` 覆盖邀请原子性、本人同意/拒绝、失效、配额及重放、同意时历史边界、格式迁移、搜索过滤与旧行隔离、网格尺寸与滚动、名称编辑、拒绝重试、离页取消票据。另执行既有聊天、输入、布局和完整工程检查。

测试不能替代游戏内多人验收。请用双方相同的预览包，至少三个玩家分别检查：选在线/离线好友建群，群名单/人数，中文/英文/多行昵称与气泡，收发文字与静态/动画图片，选字复制，个人删除后另一成员仍可见，保存重进不恢复删除，普通成员退出，群主解散，以及 GUI/HUD、附件页返回与私聊切换。

视觉效果需要实测截图确认。预览包不自动安装到游戏、不启动或关闭现有游戏、不修改玩家存档。
