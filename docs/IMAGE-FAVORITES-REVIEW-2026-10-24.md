## 发现与处理

1. **功能缺陷：瞬时加载提示被当作持久操作结果。** 在正文尚未加载时点复制，`ChatFavoritePane` 会保存 `favorite.loading` 到 status；后台加载完成只更新内容，提示不会消失。图片尚未加载时点导出也有相同路径。已用真实点击方法复现文字路径，修正为由正文加载状态显示读取／损坏提示，操作结果只记录保存和移除的结果，不再重复保存加载状态。
2. **不必要的类型耦合。** 收藏回调仍携带完整文字参数，实际生产代码已忽略它，图片则传入 null。现只传会话及消息 ID，由会话查找完整消息并决定存储内容；复制文字仍保留自己的选区规则。修改限于内部消息菜单及调用方，没有改动对外 api 包、网络或服务器。
3. **异步缓存不便验证。** 页面已注入后台和界面执行器，缓存却另外定位全局执行器，导致测试不能控制真实缓存的回调顺序。现缓存使用同一组注入的执行器，没有新增执行器池或通用媒体框架。新增真文件测试检查四项并行限制、重复请求、关闭、换环境、同键重建、缺失／损坏文件和缓存逐出。
4. **维护文档过时。** `CHAT-PROFILE.md` 仍描述仅文字、格式 1 单文件、保存会话名字，已更新职责表及存储说明，并链接 `FAVORITES.md` 作为详细规则来源。

## 工程边界复核

- `FavoriteEntry` 与 `FavoriteCodec` 维护身份、类型及元信息；索引没有重复正文、Base64 或任意文件路径。消息身份与显示名分离。
- `FavoriteStore` 只管理一个本机环境；保存先内容后索引，索引失败回收未提交文件。移除先索引后文件，删除文件失败允许下次清理。旧 JSON 只作为迁移备份，新索引损坏不会重新导入旧快照。
- 渲染读取不可变快照，不等待写盘锁；写入队列有上限，同一路径复用写入者。切服后任务仍绑定发起时的环境，不重新读取当前账号。
- `FavoriteMedia` 管理本机内容与贴图缓存，异步结果检查来源、代次及条目身份；不复用聊天服务器图片缓存。贴图上传和释放沿用已有 ImageCodec，在渲染执行器处理。
- 页面负责选中项、滚动和操作提示，消息菜单只交出意图。没有让服务器、加载器或个人资料模块理解收藏文件布局。
- `audio/`、`file/` 保留目录，不提前增加未知类型、引用计数、跨记录去重或通用插件机制。未来增加媒体类型仍需明确实现对应元信息校验、内容读写和展示路径。
