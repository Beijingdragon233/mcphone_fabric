# 收藏的本机存储

收藏按账号与存档／服务器隔离。身份仍由会话类型、会话 ID 和消息 ID 组成，不依赖显示名字。
列表与详情标题均只显示发送者。文字、静态图和动图在同一列表按收藏时间排列。

```text
config/mcphone/chat/favorites/<账号 UUID>/
├── <环境摘要>.json          原文字格式的迁移备份（若存在）
└── <环境摘要>/
    ├── index.json          format=2，身份、发送者、时间、类型、字节数、帧信息
    ├── text/<收藏摘要>.txt  UTF-8 正文，保留换行与表情
    ├── image/<收藏摘要>.png 聊天实际收到的 PNG，动图为完整帧表
    ├── audio/              仅预留目录，本版没有音频收藏
    └── file/               仅预留目录，本版没有普通文件收藏
```

环境摘要沿用原来的本地世界目录或服务器地址摘要；内容文件名由收藏身份计算，索引不保存任意文件路径。
图片以本机独立文件保存，不因服务器删除原消息、清理图片或聊天缓存逐出而消失。
收藏保留的是聊天中的画质，不是发送前未压缩的照片。图尚未加载、已过期或损坏时提示无法收藏。
重复收藏同一消息不增加记录和文件，不同消息各自拥有文件，不使用跨记录引用计数。

## 迁移与失败行为

首次访问收藏时在后台加载或迁移，期间显示“正在读取”。只有旧版 JSON 全部验证通过，才写入独立文本及新索引。
原 JSON 始终保持原样作为迁移备份。迁移失败保留原文件并报告存储错误，排除读写问题后重启游戏可重试。
新索引存在时优先使用新索引；即使新索引损坏，也不会回退旧备份而让已删除的收藏复活。
迁移备份是历史副本，后续移除收藏不会改写它；确认迁移完成后，可自行归档该旧 JSON。
升级后若退回只支持旧格式的版本，它不会识别新索引及升级后新增的收藏。

保存先原子替换内容文件，再原子发布索引；两者成功后才提示“已收藏”。索引提交失败时回收未提交内容。
移除先更新索引，再清理内容；索引失败保留原记录和文件，文件清理失败写入日志，下次载入可回收。
只回收本环境中符合受管命名、又没有索引引用的 text/image 文件，不处理其他文件名或预留目录。
单个内容文件缺失或损坏时，该条显示错误且仍可移除，不会清空其他收藏。

## 资源和操作约束

- 每个账号／环境共最多 512 条收藏，索引上限 2 MiB，图片目录总上限 128 MiB。
- 单图使用既有聊天上限（最大 768 KiB），帧表最长边 1024 像素，最多 36 帧；保存前检查 PNG 与帧信息一致。
- 动图列表显示第一帧，详情按原播放间隔播放；保存到相册沿用聊天规则，仅导出第一帧。
- 读盘、写盘、PNG 验证和解码在后台执行；只有贴图上传、释放及界面更新在渲染线程。
- 每个环境有界串行提交，最多排队 16 个操作；后台任务绑定发起时的存储对象，切服不会写进另一环境。
- 同路径复用写入者，忙碌环境不逐出；闲置环境缓存保留至多 8 份，避免快速切服产生相互覆盖的写入者。
- 内容缓存最多并行加载 4 项，元数据最多 64 项，贴图预算 24 MiB；退出收藏或切换来源时释放。
- 内容缓存使用页面注入的后台与渲染执行器；加载状态直接由内容呈现，避免按钮点击留下过期的“正在读取”提示。

## 验证

各平台工程：`assertTestFavoriteStoreTest assertTestFavoriteImageStoreTest assertTestFavoriteMediaTest assertTestChatFavoritePaneTest assertTestChatFavoriteActionsTest assertTestChatMessageActionsTest`。
新增真文件测试覆盖迁移、完整动图、重启读图、重复身份、失败回滚、缺失内容、容量、队列顺序与后台写入不阻塞排队。
缓存专项以可控队列验证加载限额、重复请求、条目移除／同键重建、关闭／换环境后的迟到结果隔离和坏文件；不创建 GL 贴图，实际显存上传和释放仍需游戏内验证。
游戏内还需检查图片右键菜单、混合列表滚动、手机／平板预览、动图、相册导出、取消收藏和重进服务器后的读取。
